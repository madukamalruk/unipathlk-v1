# Agent and engineering contracts

## Product agents

- **Aspiration lens:** visits actual offerings and explains selected-field alignment. A field match is not a career guarantee.
- **Fiscal lens:** computes a labelled cash-flow estimate or an incomplete result; never invents missing costs.
- **Gatekeeper lens:** applies pass/fail/unknown prerequisites. Later-stage eligibility is re-evaluated with the branch's accumulated qualifications.
- **Bridge lens:** identifies sourced progression participation and exposes its conditions; never mutates the catalogue.
- **Branch search walker:** explores graph edges using copied states, cycle guards and explicit stage/state/candidate caps. Pruning events describe work actually performed.
- **Planner:** Gemini selects typed, allowlisted actions and known IDs. Deterministic validation can reject a proposal. A maximum of four actions and a 15-second session budget apply.

Student findings are request-local. Shared nodes never hold student budgets, profiles, verdicts or conversation histories. Source claims remain institution facts, not model assertions.

## Read before engineering

Read requirements, architecture, tasks and current memory. Use the installed Jac version's own guides. Preserve unrelated edits and original provenance. Our conversation uses Sinhala; code, UI and product documentation use English.

Plan an increment, implement a small change, run the appropriate checker and behavioural tests, fix failures and update actual evidence. Never replace a failed assertion with a weaker one merely to get green results. Generic React/Python/framework examples are not Jac syntax.

## Team coordination authorised by the owner

The owner explicitly requested use of coding agents, skills and a council/loop workflow. Root engineer owns services, runtime, integration, documentation and publication. UI engineer owns components/styles; catalogue reviewer owns real catalogue and its evidence notes; test engineer owns tests and test matrix. Give bounded file ownership, exchange contracts and integrate under one root. Product walkers are separate from these development roles.

Do not print keys, dump environment variables, access unrelated credentials, commit .env/caches, add hidden client engines, overwrite teammates' files or publish failing work as complete. Local verification precedes JacHammer deployment. GitHub target: madukamalruk/unipathlk-v2. Any blocked external step must be reported accurately; accounts, purchases, key rotation and messages are not implicitly authorised beyond the user's request.

Catalogue reviewer independently checked official retake policy and six practical offerings. UI engineer authored the dashboard/clock/retake/guide components. Test engineer identified partial-grade, nested-input, framework-account, body-bound and static-path risks and supplied independent cases. Root integrated/fixed code, consolidated duplicate cases and ran final verification. These are development roles; no Claude-specific external council tool or hidden reasoning output is claimed.


## Verified runtime boundary

LensWalker is one parameterised walker instantiated three times: Aspiration, Fiscal, Gatekeeper. Bridge is a derived projection finding, not a separate walker or LLM agent. Planner search/evaluate are mandatory initial actions; later choice is constrained clarification/finish/tie-breaking. Request-local variables are short-lived planning state, not persistent agent memory. Development reviewers are not a runtime council. Keep these distinctions in the demo and README.
